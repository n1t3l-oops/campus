# Дневник.ру: статус интеграции Campus

Дата проверки: 2026-11-11

## Подтверждено

- Регион пользователя: Омская область; вход в региональную систему выполняется через ЕСИА на `https://55.dnevnik.ru`.
- Официальная инструкция Дневник.ру подтверждает обязательный вход через ЕСИА для Омской области.
- У Дневник.ру существует Partner API v2. Сторонние открытые клиенты описывают методы расписания ученика `/v2.0/persons/{person}/groups/{group}/schedules` и расписания учебной группы `/v2.0/edu-groups/{eduGroup}/timetables`.
- Наличие этих методов в сторонних клиентах не подтверждает, что произвольному стороннему приложению разрешён доступ или что старый OAuth-flow совместим с региональным входом через ЕСИА.
- Повторная проверка 11.11.2026: официальная страница Partner API Swagger не открылась в доступном просмотре; подтверждения OAuth-flow для омской ЕСИА и доступа к АИС «Дневник-ПОО» не найдено. Поэтому интеграцию нельзя реализовывать на основании одних сторонних библиотек.

## Безопасное архитектурное решение

Campus — статическая PWA на GitHub Pages. Нельзя помещать OAuth client secret, access token, refresh token, пароль или данные ЕСИА в `index.html`, другие публичные файлы или Git history.

Перед реализацией реального подключения необходимо подтвердить у Дневник.ру/оператора региональной системы:

1. Разрешён ли доступ стороннего пользовательского приложения к расписанию обучающегося через Partner API.
2. Какой OAuth grant / authorization flow поддерживается для Омской области после входа через ЕСИА.
3. Нужна ли регистрация приложения и какой client_id должен использоваться.
4. Какие scopes и endpoints разрешены для профиля обучающегося СПО.
5. Разрешено ли хранение/обработка расписания сторонним приложением и какие требования предъявляются к токенам.

Официальная инструкция по входу: https://support.dnevnik.ru/195-214-314--avtorizaciya-cherez-portal-gosuslug-dlya-omskoj-oblasti/

Официальная документация Partner API: https://api.dnevnik.ru/partners/swagger/ui/index

Сторонний справочный проект (не является подтверждением официального разрешения): https://github.com/kesha1225/DnevnikRuAPI


## Новая находка: неофициальная интеграция для регионов с ЕСИА (11.11.2026)

Найден архивный проект [SiroXYZ/DnevnikRuAPI_NEW](https://github.com/SiroXYZ/DnevnikRuAPI_NEW), автор которого заявляет поддержку регионов, где вход выполняется через Госуслуги. В README перечислены методы расписания и получение данных через API. Это делает вариант с API более перспективным, чем считалось ранее, но не является гарантией работы именно с Омской областью или с текущим профилем СПО.

Важное ограничение безопасности: проект архивирован, а описанный способ получения токена ведёт на сторонний сервис. Не использовать этот сервис и не передавать ему данные ЕСИА, пароль, коды или токены. Неофициальный проект можно изучать только как источник сведений об API; авторизацию нужно проводить на официальном домене Дневник.ру/ЕСИА и сохранять состояние локально.

## Предлагаемый следующий эксперимент

1. Локальный Playwright открывает официальный адрес https://55.dnevnik.ru в отдельном постоянном профиле браузера.
2. Пользователь самостоятельно проходит вход через ЕСИА в официальном окне.
3. Скрипт проверяет, открывается ли расписание группы БП314 и может ли страница предоставить данные занятий.
4. Только после подтверждения чтения данных выбирается способ безопасной синхронизации с Campus. Не помещать профиль браузера, cookies, токены или персональные данные расписания в GitHub.

Этот эксперимент потребует, чтобы компьютер был включён во время проверок. Для круглосуточной работы понадобится отдельный постоянно работающий сервер и безопасный способ первичной авторизации на нём.

## Следующий этап реализации

После подтверждения официального OAuth-flow:
- добавить отдельный модуль интеграции, не смешивая его с OCR;
- использовать только разрешённые endpoints и scopes;
- хранить секреты только на серверной стороне, если они вообще выдаются приложению;
- не передавать токены в GitHub Pages;
- нормализовать расписание в формат Campus;
- сравнивать снимки расписания и показывать изменения до применения;
- сохранить OCR/ручной импорт как резервный источник.

До получения этих сведений автоматическое подключение не реализуется. Campus остаётся на текущем расписании и ручном внесении изменений через существующий интерфейс распознавания изображений; CSV-импорт не используется. Не применять обход ЕСИА, сбор паролей/cookies или передачу токенов в публичную PWA.
